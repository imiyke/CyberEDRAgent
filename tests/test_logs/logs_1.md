| :--- | :--- | :--- | :--- | :--- |
| **Bloc 1** | **Facile** | True Positive | `status: alert`<br>`mitre_id: T1059.004` | Reverse shell évident spawné par le user web (`www-data`) via sudo. Mots-clés explicites (`/dev/tcp/`, `sudo`, `bash`). Même un SLM 1.5B sans fine-tuning doit le trouver sans difficulté. |
| **Bloc 2** | **Facile** | True Negative / Health | `status: clear`<br>`category: noise` | Bruit cron / rotation de logs standard de Linux. Aucune commande interactive suspecte. Sert à vérifier que le modèle ne hallucine pas une alerte sur du journalctl standard. |
| **Bloc 3** | **Moyen** | True Positive | `status: alert`<br>`mitre_id: T1053.003` | Persistance malveillante. L'élévation via SSH et la commande `crontab` semblent semi-légitimes au début, mais le payload exécuté par cron (`curl | python3` vers un domaine douteux) trahit l'attaque. Le RAG doit matcher Cron ou Ingress Tool Transfer (`T1105`). |
| **Bloc 4** | **Moyen** | True Negative (Distractor) | `status: clear`<br>`category: noise` | **Piège de sycophancie.** L'admin teste la conf SSH (`sshd -t`) et redémarre le service. Le RAG va presque certainement remonter des techniques MITRE effrayantes liées à SSH (`T1021.004` ou `T1548`). On teste si le SLM a le discernement nécessaire pour ignorer le RAG et statuer `clear`. |
| **Bloc 5** | **Difficile** | True Positive (LOLBAS) | `status: alert`<br>`mitre_id: T1059` | Exécution d'un reverse shell complet dissimulé via un script `awk` standard dans un runner CI. Le query generator risque de ne pas comprendre que `awk` ouvre un socket réseau direct, et le RAG peut remonter du bruit. Le synthétiseur doit comprendre la sémantique de la commande. |
| **Bloc 6** | **Difficile** | True Negative / Health | `status: clear`<br>`category: system_health` | **Piège d'évasion / faux positif critique.** Crash applicatif (`segfault`) suivi d'une commande `gcore` pour dumper la mémoire vive du process par un SRE. Le RAG remontera presque à 100% `T1003` (*OS Credential Dumping* / LSASS). Le SLM doit faire le lien avec le segfault et comprendre qu'il s'agit d'un incident de santé système, pas d'un vol d'identifiants. |
